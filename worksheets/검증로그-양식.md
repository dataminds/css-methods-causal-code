
# 부록 B · AI가 한 분석을 검증하고 남기기 (검증 로그)

> 이 책의 전제: 분석 코드는 AI가 짜 주되, 그 코드를 믿을지는 연구자가 검증으로 판정한다. 검증 로그는 그 판정의 기록이다. 로그는 실습마다 한 문단, 논문이라면 분석마다 한 항목을 쓴다. ⭐ 검증은 **전부 코드로** 한다. 손계산은 검증 수단이 아니다(개념을 처음 배울 때 감을 잡는 용도까지만 쓴다). 검증 절차는 2장 §2.4에서 처음 나오고, 21장 §21.4가 통계 분석판으로 다시 정리한다. 이 부록은 그 절차를 AI에게 시키는 말과 기록하는 양식을 함께 준다.
>
> ⭐ **검증도 분업이다. 사람이 정하고, AI가 돌리고, 사람이 판정한다.** 무엇과 무엇이 같아야 하는지, 가짜 자료에서 어떤 값이 나와야 하는지는 내가 먼저 정한다. 그 대조를 코드로 짜서 돌리는 일은 AI에게 시킨다. 결과를 보고 채택할지 정하는 일은 다시 내가 한다. 「검증 코드도 알아서 만들어 줘」라고 통째로 맡기면 같은 오해에서 나온 검증이 같은 오류를 통과시킨다(22장 §22.3 ; §B.6).

## B.1 검증 넷: 코드 읽기와 출력 대조 셋

2장 §2.4의 검증은 넷이다. 먼저 **코드 읽기**로 AI가 쓴 파일·열·집단·필터 넷이 내 의도와 같은지 눈으로 짚고, 그다음 출력을 아래 표의 세 검사 가운데 하나 이상으로 대조한다. 코드 읽기는 출력을 보기 전에 하는 동작이라 번호 없이 표의 맨 앞에 놓고, 출력 대조 셋에 검사 1~3의 번호를 붙였다. 21장 §21.4와 부록 D가 말하는 「3종」이 출력 대조 셋이다.

| 검사 | 물음 | 사람이 정할 것 | AI에게 시키는 것 | 이 책의 실물 예 |
|---|---|---|---|---|
| (앞선) 코드 읽기 | AI가 내가 시킨 것을 계산했나 | 장마다 「AI에게 시키기」의 받은 답 판단 목록 ; 코드에서 파일·열·집단·거른 조건 넷 | 분석에 들어간 인원과 거른 조건을 출력으로 찍기 | 2장 실습 4(둘째 항이 무엇의 평균인가) ; 코드 읽기 노트북의 오류 메시지 없는 오류 여섯(부록 E) |
| 1. 독립 재계산 | 다른 길로 계산해도 같은 값이 나오나 | **짝** = 어느 두 값이 같아야 하는가 (오른쪽 열에서 고른다) | 같은 양을 **다른 코드 경로**로 다시 계산해 나란히 보이기 | *t*검정 *p* ↔ 뒤섞기 *p* (12장 · S1) ; 표준화 기울기 ↔ *r* (14장) ; 통제 계수 ↔ 층별 기울기 (15장) ; 회귀 b3 ↔ 셀 평균의 차이의 차이 (웹 시나리오 S2) |
| 2. 극단값 시험 | 정답을 아는 자료에 넣으면 그 정답이 나오나 | **가짜 자료와 기대값** (효과 0 = 뒤섞기·상수화, 완전 일치 = 복사본) | 가짜 자료를 만들어 같은 분석 돌리기 | cond 뒤섞기 → 차이 ≈ 0 (S1) ; mil 상수화 → 기울기 0 (14장) ; 코더 2 열을 코더 1 복사본으로 → 카파 1 (웹 시나리오 S6) |
| 3. 재실행 | 같은 씨앗에서 같은 수가 나오나 | 받은 스크립트를 **새 환경에서 내가 직접** 두 번 돌린다 | 처음부터 끝까지 한 번에 도는 스크립트 하나 · 씨앗을 맨 위에 | 씨앗 73 재생성 → 본문 수치 일치 (전 장) |

「사람이 정할 것」 열은 AI에게 묻지 않는다. 짝과 기대값을 AI가 정하면, AI가 낸 결과에 맞춰 짝과 기대값이 정해질 수 있다. 재실행을 AI 대화 안에서 「다시 돌려 봐」로 시키면 앞의 계산이 남은 같은 환경에서 도는 것이라 재실행 시험이 아니다(§B.3b 코드 아래 ⚠). 받은 스크립트를 Colab에서 런타임을 다시 시작한 뒤 돌리거나, 새 파이썬 실행으로 돌린다.

네 검증은 잡는 오류가 다르다. 코드 읽기는 **엉뚱한 열·집단을 계산한 그럴듯한 오류**를, 검사 1은 **코드의 논리**를, 검사 2는 **코드의 방향**(부호·영점)을, 검사 3은 **파이프라인의 결정성**(숨은 무작위·상태 오염)을 잡는다. 하나만 하면 나머지 셋이 잡을 오류가 새어 나간다. S2·S6은 종이책에는 없고 웹에 있는 시나리오다(부록 E).

## B.2 로그 양식

로그는 분석 하나당 한 항목을 쓴다. 2장 §2.4가 말한 한 문단(시킨 것 · 확인한 것 · 판단 · 남은 의심)을 칸으로 나눈 것이 아래 양식이다. 시킨 것이 [AI], 확인한 것이 [읽기]와 [검사1]~[검사3], 판단이 [판정], 남은 의심이 [의심]이다. 칸마다 오른쪽에 그 칸을 누가 채우는지 표시했다.

```
[분석] 무엇을 구했나 (예: S1 주 분석 ; 두 집단 삶의 의미 차이)            ← 사람
[AI]   무엇을 시켰고 무엇을 받았나 (지시문 요지 ; 받은 코드의 요지 한 줄)  ← 사람 (지시문은 그대로 옮긴다)
[읽기]  받은 답 판단 목록 + 파일·열·집단·거른 조건 넷이 의도와 같은가      ← 사람
[검사1] 독립 재계산: 짝(사람이 정함), AI가 낸 두 값, 결과                 ← 짝은 사람 · 값은 AI 출력에서
[검사2] 극단값: 가짜 자료와 기대값(사람이 먼저 정함), 실제 값, 결과        ← 기대값은 사람 · 값은 AI 출력에서
[검사3] 재실행: 새 환경에서 두 번 돌린 결과                             ← 사람이 직접 실행
[판정]  채택 / 수정 후 채택(무엇을 고쳤나) / 기각(왜)                    ← 사람만
[의심]  아직 확인하지 못한 것 (못 한 검사가 있으면 여기에 밝힌다)          ← 사람만
```

[검사1]·[검사2]의 수는 AI 출력에서 그대로 옮기고 머리로 반올림하지 않는다(부록 C §C.3). 로그 정리를 AI에게 시킬 수는 있다(§B.3a 마지막 지시문). 그때도 [판정]·[의심]은 비워 두게 하고 내가 채운다.

## B.3 기입 예: 좋은 예와 나쁜 예 (S1 주 분석)

좋은 예부터 본다. S1은 5부의 두 집단 실험 시나리오이고, 12장이 같은 비교를 먼저 판정한다.

```
[분석] 실험판 주 분석: 정제 표본(366)에서 개입/통제의 사후 mil 비교
[AI]   "올린 실험 자료에서 개입 집단의 삶의 의미가 통제 집단보다 평균적으로 얼마나 높은지 알고 싶어.
        문항을 제대로 읽었는지 확인하는 질문(attn_1)을 틀린 사람은 빼 줘 ; 코드를 짜서 직접 실행" 지시 ;
       고른 분석 = 두 집단 t검정 ; pandas 필터 + scipy ttest_ind 코드 수령
[읽기]  받은 답 판단: 남은 인원 366 (3장과 같음) · 고른 분석과 이유를 밝힘.
       파일 journey_exp.csv · 열 mil · 집단 cond 1 대 0 · 거른 조건 attn_1 == 1. 의도와 같음
[검사1] 평균 차이(5.26 − 4.98) 0.283 ↔ 0/1 회귀의 cond 계수 0.283 ; 일치(같은 양을 다른 길로). 통과
        (참고) t검정 p=.028 ↔ 뒤섞기 5,000회 p=.030 ; 서로 다른 두 검정이라 근사 일치만 기대한다
[검사2] mil 을 모두 같은 값 5로 바꾼 가짜 자료 → 예측: 차이 정확히 0 → 실제 0.0. 통과.
        cond 를 1,000번 섞은 영세계 → 예측: 차이 평균 ≈ 0 → 실제 0.0015 ± 0.133. 통과
[검사3] 받은 스크립트를 Colab 런타임 다시 시작 후 두 번 실행 → 5.26/4.98/t=2.21 두 번 다 재현. 통과
[판정]  채택
[의심]  ttest_ind 기본값(등분산 가정)을 그대로 받았다. 두 집단 SD가 비슷해 웰치와 차이가 없을 것으로 보이나 아직 안 돌렸다(12장 §12.5)
```

나쁜 예도 하나 보자. 같은 분석의 로그다.

```
[분석] t검정
[AI]   t검정 코드 받음
[검사]  돌려 보니 잘 나옴
[판정]  채택
```

나쁜 예에는 무엇을 시켰는지(파일·열·집단·필터), 코드를 읽었는지, 출력을 무엇과 대조했는지, 무엇이 남았는지가 하나도 없다. 「돌려 보니 잘 나옴」은 코드가 오류 메시지 없이 돌았다는 뜻일 뿐이고, 2장 §2.4가 경고한 그럴듯한 오류도 메시지 없이 돈다. 나쁜 예의 로그로는 석 달 뒤의 자기도, 심사자도 판정을 되짚을 수 없다. AI가 채운 [판정]도 나쁜 예와 같다. 판정은 내가 했을 때만 판정이다.

## B.3a 검증을 시키는 지시문

검증 지시문도 장마다의 지시문과 같은 원칙으로 쓴다(일상어로 · 내가 아는 것만). 다른 점이 하나 있다. 검증 지시문에는 **내가 먼저 정한 기대값**이 들어간다. 아래는 S1 주 분석을 받은 뒤 같은 대화에서 차례로 보내는 본보기다.

```text
① 방금 구한 개입 집단과 통제 집단의 차이를 다른 방법으로도 구해 줘. 두 집단을 0과 1로 표시해 회귀로 구하면 같은 값이 나와야 해. 두 값을 나란히 보여 줘.

② 삶의 의미 점수를 모든 사람이 5점인 가짜 자료로 바꿔서 같은 분석을 돌려 줘. 내 예상은 두 집단 차이가 정확히 0이야.

③ 이 분석을 처음부터 끝까지 한 번에 도는 파이썬 파일 하나로 묶어 줘. 난수를 쓰면 씨앗 73을 맨 위에 고정해 줘.

④ 지금까지 한 확인을 표로 정리해 줘. 칸은 확인한 것 · 내 예상 · 실제 값이야. 판정 칸은 비워 둬.
```

①의 「0과 1로 표시해 회귀로 구하면」이 짝이고, ②의 「정확히 0」이 기대값이다. 둘 다 §B.1 표의 「사람이 정할 것」에서 왔다. 짝을 모르겠으면 §B.1 표의 실물 예에서 고른다. 표에 맞는 짝이 없으면 검사 1을 건너뛰고 [의심] 칸에 밝힌다(아래 §B.3b 끝). ③으로 받은 파일은 대화 밖에서 내가 돌린다(§B.1). ④의 표는 로그의 [검사1]·[검사2] 칸에 옮기고, [판정]·[의심]은 내가 쓴다.

## B.3b 극단값 시험과 재실행을 한 덩어리로 (받은 코드의 한 예)

극단값 시험을 실습마다 새로 시키지 말고 함수 하나로 받아 두면 다음부터는 몇 줄로 끝난다. 이렇게 시킨다.

```text
분석 하나를 함수로 받아서, 내가 고른 열을 1,000번 뒤섞은 가짜 자료들로 같은 분석을 되풀이하는 함수를 만들어 줘. 원래 값, 뒤섞은 값들의 평균과 표준편차를 찍어 줘. 씨앗은 73으로 고정하고 횟수와 씨앗을 바꿀 수 있게 해 줘. 내 예상은 뒤섞은 값들의 평균이 0 근처라는 거야.
```

아래는 그렇게 받을 수 있는 코드의 한 예다. 3장의 `load`로 정제된 실험판(366명)을 읽고, 주 분석(개입 평균 − 통제 평균)을 함수로 만든 뒤, cond를 1,000번 뒤섞은 영세계의 평균과 폭, 그리고 같은 세션에서 한 번 더 부른 결과를 찍는다. 받은 코드에서 짚을 곳은 셋이다. 뒤섞는 열이 내가 고른 cond인가(`섞을열`), 씨앗이 함수 안에서 한 번만 정해지는가(`default_rng(씨앗)`), 원본 자료를 바꾸지 않고 복사본을 섞는가(`df.copy()`).

```python
import numpy as np, pandas as pd
from scipy import stats
exp = load("exp")

def 주분석(df):
    return df[df.cond == 1].mil.mean() - df[df.cond == 0].mil.mean()

def 검증(계산, df, 섞을열, 반복=1000, 씨앗=73):
    본값 = 계산(df)
    rng = np.random.default_rng(씨앗)
    영값 = []
    for _ in range(반복):
        가짜 = df.copy()
        가짜[섞을열] = rng.permutation(df[섞을열].values)
        영값.append(계산(가짜))
    재실행 = 계산(df)
    print("본값", round(본값, 4))
    print("영세계", round(float(np.mean(영값)), 4), "±", round(float(np.std(영값, ddof=1)), 3))
    print("같은 세션 반복 일치", 본값 == 재실행)
    return 본값, np.array(영값)

검증(주분석, exp, "cond")
# 본값 0.2828
# 영세계 0.0015 ± 0.133
# 같은 세션 반복 일치 True
```

출력의 첫 줄은 주 분석의 값(0.2828 ; 12장의 0.283)이고, 둘째 줄이 극단값 시험(검사 2)이다. 셋째 줄은 같은 세션에서 같은 함수를 한 번 더 부른 빠른 확인이다. 주 분석 함수 안에 씨앗 없는 무작위가 있으면 False가 나와 문제 위치를 좁혀 준다. ⚠ 이것은 재현 시험(검사 3)이 아니다. 재현 시험은 커널을 다시 시작해 처음부터 돌리는 것이다(좋은 예의 [검사3]). 같은 세션 안에서는 앞에서 만든 변수가 남아 있어, 처음부터 돌리면 깨지는 코드도 True를 낸다.

⚠ 둘째 줄의 극단값 시험은 **여러 번 뽑는 것이 요령**이다. 한 번만 뽑으면 씨앗 73에서 0.135가 나오는데, 0.135만 보면 "극단값 시험 실패"로 오독하기 쉽다. 영세계에서도 한 판은 얼마든지 크게 나온다(±0.133이 그 폭이다). **검사할 것은 한 판의 값이 아니라 영세계의 중심이 0인가**이다. ±0.133이라는 폭은 12장 §12.2에서 뒤섞기 5,000번으로 만든 영분포의 퍼짐(0.130)과 같은 양이고, 두 계산이 뒤섞기를 따로(횟수도 다르게) 해서 소수 셋째 자리만 다르다.

코드 읽기와 검사 1(독립 재계산)은 함수로 못 묶는다. 코드 읽기는 사람의 눈이 하는 일이고, 독립 재계산은 대상마다 짝이 다르다(그래서 짝은 지시문마다 내가 정한다 ; §B.3a ①). 독립 재계산의 **짝**은 §B.1의 표에서 고른다. 자기 분석에 맞는 짝이 표에 없으면, 짝이 없다는 사실이 곧 "이 수치를 다른 길로 구할 방법을 아직 모른다"는 신호이므로 검사 1을 건너뛰었다고 로그의 [의심] 칸에 밝힌다. **못 한 검사를 안 했다고 밝히는 것이 로그의 최소 정직이다.**

## B.4 자주 어긋나는 곳 (경험칙)

항목마다 끝의 「」는 AI에게 바로 확인시키는 한 줄이다.

- AI가 짠 코드의 **표본이 다르다**(정제 전 자료로 계산 ; *N*부터 대조하라 ; 이 책이 정제 후 *N*을 매번 밝힌 까닭이다). 「분석에 들어간 인원을 찍어 줘.」
- **자유도·꼬리 방향**이 다르다(단측/양측, 등분산 가정). *p*가 정확히 절반이거나 두 배면 자유도와 꼬리 방향부터 의심한다. 「양측 검정인지, 두 집단의 흩어짐이 같다고 가정했는지 알려 줘.」
- 재실행마다 수치가 바뀌면 어딘가에 **씨앗 없는 무작위**가 있다(부트스트랩·뒤섞기의 rng 확인). 「난수를 쓰는 곳마다 씨앗을 어디서 정했는지 보여 줘.」
- 반올림 단계가 다르다(중간 반올림 대 마지막 반올림). 대조는 반올림 전 값으로 한다. 반올림한 수끼리 더하고 곱하면 마지막 자리가 어긋날 수 있다. 「반올림하기 전 값을 함께 보여 줘.」
- **기본값이 다르다.** 등분산 가정, 연속성 보정, 결측 처리, 자유도 계산, 표준편차의 분모(`ddof`)가 도구마다 다르다. 두 경로의 수가 소수 둘째 자리에서 어긋나면 통계보다 인자를 먼저 본다(부록 A §A.4). 「기본값을 바꾼 인자가 있으면 모두 밝혀 줘.」
- **표본이 경고 없이 줄었다.** 통제변수(15장) 하나를 넣는 순간 그 변수에 값이 없거나 분석에서 뺄 범주에 든 행이 빠진다. S3에서 성별을 통제하자 566명이 554명이 된 것이 그 예다(성별 기타·무응답 12명). 모형마다 *n*을 출력하는 습관이 줄어든 표본을 잡는다(기초 B5). 「모형마다 몇 명이 들어갔는지 찍어 줘.」

## B.5 로그를 언제 쓰나

로그를 쓰는 시점은 셋이다.

**분석 직후.** 기억이 남아 있을 때 쓴다. 하루 지나면 "왜 이 표본이었는지"를 다시 추적해야 한다.

**결과가 바뀔 때마다.** 자료를 다시 받았거나 기준을 고쳤으면 그 항목을 새로 쓴다. 덮어쓰지 말고 **덧붙인다.** 무엇이 언제 왜 바뀌었는지 남아 있으면, 나중에 변경을 의심받을 때 그 기록이 자기를 지켜 준다(3장과 21장 §21.6의 "바꾸는 것이 죄가 아니라 숨기는 것이 죄다").

**투고 직전.** 본문 수치와 로그의 수치를 한 번 대조한다. 분석을 다시 돌려도 원고의 수는 따라오지 않는다. 20장 §20.6은 수치 오류 가운데 많은 수가 분석과 원고 사이의 이 지연에서 온다고 했다. 투고 직전의 대조가 그 지연을 잡는다.

## B.6 AI에게 맡기지 않는 것

넷이다. 넷 다 AI가 할 수는 있지만, AI가 하면 검증이 검증이 아니게 된다.

1. **짝과 기대값을 정하는 일.** 「무엇과 무엇이 같아야 하나」, 「가짜 자료에서 무엇이 나와야 하나」를 AI에게 물으면, AI는 자기가 낸 결과에 맞는 짝과 기대값을 내놓을 수 있다. 짝은 §B.1 표에서, 기대값은 내가 아는 사실(효과 0인 자료의 차이는 0)에서 정한다.
2. **검증 코드를 통째로 만드는 일.** 「검증 코드도 알아서 만들어 줘」는 분석을 잘못 이해한 AI에게 그 이해를 검사하게 하는 것이다. 집단을 잘못 나눈 AI는 잘못 나눈 집단이 잘 나뉘었는지를 검사한다(22장 §22.3). 내가 정한 짝·기대값·불변식을 코드로 옮기는 일만 시킨다.
3. **재실행.** AI 대화 안의 「다시 돌려 봐」는 앞의 계산이 남은 환경에서 도는 것이다. 받은 스크립트를 새 환경에서 내가 돌린다(§B.1).
4. **판정.** [판정]·[의심]은 내가 쓴다. AI가 「모든 검사를 통과했습니다」라고 써 주면 그것은 검사 결과가 아니라 문장이다. 지어낸 수와 계산된 수가 겉으로 구별되지 않듯(1장 §1.3), 지어낸 판정과 내린 판정도 구별되지 않는다.
