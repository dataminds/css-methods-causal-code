
# 부록 B · 검증 로그 양식 (통계판)

> 이 책의 전제: 분석 코드는 AI가 짜 주되, 그 코드를 믿을지는 연구자가 검증으로 판정한다. 검증 로그는 그 판정의 기록이다. 실습마다 한 문단, 논문이라면 분석마다 한 항목. ⭐ 검증은 **전부 코드로** 한다. 손계산은 검증 수단이 아니다(개념을 처음 배울 때 감을 잡는 용도까지만). 검증의 절차는 2장 §2.4에서 처음 나오고, 20장 §20.4가 통계 분석판으로 다시 정리한다. 이 부록은 그 절차를 기록하는 양식이다.

## B.1 검증 넷: 코드 읽기와 출력 대조 셋

2장 §2.4의 검증은 넷이다. 먼저 **코드 읽기**로 AI가 쓴 파일·열·집단·필터 넷이 내 의도와 같은지 눈으로 짚고, 그다음 출력을 아래 셋 가운데 하나 이상으로 대조한다. 코드 읽기는 출력을 보기 전에 하는 동작이라 번호 없이 앞에 두고, 출력 대조 셋에 검사 1~3의 번호를 붙였다. 20장 §20.4와 부록 D가 말하는 「3종」이 이 셋이다.

| 검사 | 물음 | 방법 | 이 책의 실물 예 |
|---|---|---|---|
| (앞선) 코드 읽기 | AI가 내가 시킨 것을 계산했나 | 파일·열·집단·필터 넷을 내 의도와 대조 | 2장 실습 4(둘째 항이 무엇의 평균인가) ; 코드 읽기 노트북의 조용한 오류 여섯(부록 E) |
| 1. 독립 재계산 | 같은 답이 다른 길로도 나오나 | 같은 양을 **다른 코드 경로**로 계산해 대조 | *t*검정 *p* ↔ 뒤섞기 *p* (12장 · S1) ; 표준화 기울기 ↔ *r* (14장) ; 통제 계수 ↔ 층별 기울기 (15장) ; 회귀 b3 ↔ 셀 평균의 차이의 차이 (웹 시나리오 S2) |
| 2. 극단값 시험 | 답을 아는 자료에서 그 답이 나오나 | 효과를 0으로 만든 자료(뒤섞기·상수화·복사본)를 먹여 예측값 확인 | cond 뒤섞기 → 차이 ≈ 0 (S1) ; mil 상수화 → 기울기 0 (14장) ; 코더 2 열을 코더 1 복사본으로 → 카파 1 (웹 시나리오 S6) |
| 3. 재실행 | 같은 씨앗에서 같은 수가 나오나 | 씨앗 고정 후 처음부터 재실행해 전 수치 대조 | 씨앗 73 재생성 → 본문 수치 일치 (전 장) |

넷의 분업: 코드 읽기는 **엉뚱한 열·집단을 계산한 그럴듯한 오류**를, 1은 **코드의 논리**를, 2는 **코드의 방향**(부호·영점)을, 3은 **파이프라인의 결정성**(숨은 무작위·상태 오염)을 잡는다. 하나만 하면 나머지가 잡을 오류가 새어 나간다. S2·S6은 종이책이 아니라 웹에 있는 시나리오다(부록 E).

## B.2 로그 양식

분석 하나당 한 항목. 2장 §2.4가 말한 한 문단(시킨 것 · 확인한 것 · 판단 · 남은 의심)을 칸으로 나눈 것이 아래 양식이다. 시킨 것이 [AI], 확인한 것이 [읽기]와 [검사1]~[검사3], 판단이 [판정], 남은 의심이 [의심]이다.

```
[분석] 무엇을 구했나 (예: S1 주 분석 ; mil ~ cond t검정)
[AI]   무엇을 시켰고 무엇을 받았나 (프롬프트 요지 ; 받은 코드의 요지 한 줄)
[읽기]  코드 읽기: 파일·열·집단·필터 넷이 의도와 같은가
[검사1] 독립 재계산: 무엇 ↔ 무엇, 결과 (예: t검정 p=.028 ↔ 뒤섞기 p=.030, 근사 일치)
[검사2] 극단값: 어떤 가짜 자료, 예측, 결과 (예: cond 뒤섞기 → 예측 차이≈0 → 실제 -0.02)
[검사3] 재실행: 씨앗·결과 (예: 씨앗 73 재실행, 전 수치 일치)
[판정]  채택 / 수정 후 채택(무엇을 고쳤나) / 기각(왜)
[의심]  아직 확인하지 못한 것 (못 한 검사가 있으면 여기에 밝힌다)
```

## B.3 기입 예: 좋은 예와 나쁜 예 (S1 주 분석)

먼저 좋은 예다. S1은 5부의 두 집단 실험 시나리오이고, 같은 비교를 12장이 먼저 판정한다.

```
[분석] 실험판 주 분석: 정제 표본(366)에서 개입/통제의 사후 mil 비교
[AI]   "journey_exp.csv에서 attn_1 통과자만으로 cond별 mil 평균·SD·t검정" 지시 ;
       pandas 필터 + scipy ttest_ind 코드 수령
[읽기]  파일 journey_exp.csv · 열 mil · 집단 cond 1 대 0 · 필터 attn_1 == 1. 의도와 같음
[검사1] t검정 p=.028 ↔ 뒤섞기 5,000회 p=.030 ; 근사 일치, 채택 방향
[검사2] cond를 rng(73)으로 뒤섞은 영세계 → 예측: 차이≈0, p 큼 → 실제 p=.346. 통과
[검사3] 커널 재시작 후 씨앗 73 전체 재실행 → 5.26/4.98/t=2.21 전부 재현. 통과
[판정]  채택
[의심]  ttest_ind 기본값(등분산 가정)을 그대로 받았다. 두 집단 SD가 비슷해 웰치와 차이가 없을 것으로 보이나 아직 안 돌렸다(12장 §12.4)
```

나쁜 예도 하나 보자. 같은 분석의 로그다.

```
[분석] t검정
[AI]   t검정 코드 받음
[검사]  돌려 보니 잘 나옴
[판정]  채택
```

무엇을 시켰는지(파일·열·집단·필터), 코드를 읽었는지, 출력을 무엇과 대조했는지, 무엇이 남았는지가 하나도 없다. 「돌려 보니 잘 나옴」은 코드가 오류 없이 돌았다는 뜻일 뿐이고, 2장 §2.4가 경고한 그럴듯한 오류는 바로 그렇게 돈다. 이 로그로는 석 달 뒤의 자기도, 심사자도 판정을 되짚을 수 없다.

## B.3b 극단값 시험과 재실행을 한 덩어리로 (재사용 코드)

매번 새로 짜지 말고 함수 하나로 두면 실습마다 몇 줄이면 끝난다. 아래 코드는 3장의 `load`로 정제된 실험판(366명)을 읽고, 주 분석(개입 평균 − 통제 평균)을 함수로 만든 뒤, cond를 1,000번 뒤섞은 영세계의 평균과 폭, 그리고 재실행 결과를 찍는다.

```python
import numpy as np, pandas as pd
from scipy import stats
exp = load("exp")

def 주분석(df):
    return df[df.cond == 1].mil.mean() - df[df.cond == 0].mil.mean()

def 검증(계산, df, 섞을열, 반복=1000, 씨앗=73):
    본값 = 계산(df)
    rng = np.random.default_rng(씨앗)
    영값 = []
    for _ in range(반복):
        가짜 = df.copy()
        가짜[섞을열] = rng.permutation(df[섞을열].values)
        영값.append(계산(가짜))
    재실행 = 계산(df)
    print("본값", round(본값, 4))
    print("영세계", round(float(np.mean(영값)), 4), "±", round(float(np.std(영값, ddof=1)), 3))
    print("재실행 일치", 본값 == 재실행)
    return 본값, np.array(영값)

검증(주분석, exp, "cond")
# 본값 0.2828
# 영세계 0.0015 ± 0.133
# 재실행 일치 True
```

첫 줄은 주 분석의 값(0.2828 ; 12장의 0.283)이고, 둘째 줄이 극단값 시험(검사 2), 셋째 줄이 재실행(검사 3)이다. 셋째 줄의 `본값 == 재실행`이 False로 나오면 어딘가에 씨앗 없는 무작위가 있다는 뜻이고, 그것만으로 문제 위치가 절반은 좁혀진다.

⚠ 둘째 줄에서 **여러 번 뽑는 것이 요령**이다. 한 번만 뽑으면 씨앗 73에서 0.135가 나오는데, 그 수만 보면 "극단값 시험 실패"로 오독하기 쉽다. 영세계에서도 한 판은 얼마든지 크게 나온다(±0.133이 그 폭이다). **검사할 것은 한 판의 값이 아니라 영세계의 중심이 0인가**이다. 그 폭은 12장 §12.2에서 뒤섞기 5,000번으로 만든 영분포의 퍼짐(0.130)과 같은 양이고, 뒤섞기를 따로(횟수도 다르게) 해서 소수 셋째 자리만 다르다.

코드 읽기와 검사 1(독립 재계산)은 함수로 못 묶는다. 코드 읽기는 사람의 눈이 하는 일이고, 독립 재계산은 대상마다 짝이 다르다. 독립 재계산의 **짝**은 §B.1의 표에서 고른다. 자기 분석에 맞는 짝이 표에 없으면, 그것이 곧 "이 수치를 다른 길로 구할 방법을 아직 모른다"는 신호이고, 그때는 검사 1을 건너뛰었다고 로그의 [의심] 칸에 밝힌다. **못 한 검사를 안 했다고 밝히는 것이 로그의 최소 정직이다.**

## B.4 자주 새는 곳 (경험칙)

- AI가 짠 코드의 **표본이 다르다**(정제 전 자료로 계산 ; N부터 대조하라 ; 이 책에서 정제 후 N을 매번 명시한 이유).
- **자유도·꼬리 방향**이 다르다(단측/양측, 등분산 가정). p가 정확히 절반이거나 두 배면 이것부터 의심.
- 재실행마다 수치가 바뀐다 = **씨앗 없는 무작위**가 어딘가에 있다(부트스트랩·뒤섞기의 rng 확인).
- 반올림 단계가 다르다(중간 반올림 vs 마지막 반올림). 대조는 반올림 전 값으로.
- **기본값이 다르다.** 등분산 가정, 연속성 보정, 결측 처리, 자유도 계산, 표준편차의 분모(`ddof`). 두 경로의 수가 소수 둘째 자리에서 어긋나면 통계가 아니라 인자를 먼저 본다(부록 A §A.4).
- **표본이 조용히 줄었다.** 통제변수(15장) 하나를 넣는 순간 그 변수에 값이 없거나 분석에서 뺄 범주에 든 행이 빠진다. S3에서 성별을 통제하자 566명이 554명이 된 것이 그 예다(성별 기타·무응답 12명). 모형마다 n을 출력하는 습관이 이것을 잡는다.

## B.5 로그를 언제 쓰나

세 시점이다.

**분석 직후.** 기억이 남아 있을 때 쓴다. 하루 지나면 "왜 이 표본이었는지"를 다시 추적해야 한다.

**결과가 바뀔 때마다.** 자료를 다시 받았거나 기준을 고쳤으면 그 항목을 새로 쓴다. 덮어쓰지 말고 **덧붙인다.** 무엇이 언제 왜 바뀌었는지가 나중에 자기를 지켜 준다(3장과 20장 §20.6의 "바꾸는 것이 죄가 아니라 숨기는 것이 죄다").

**투고 직전.** 본문 수치와 로그의 수치를 한 번 대조한다. 분석을 다시 돌려도 원고의 수는 따라오지 않는다. 19장 §19.6이 수치 오류의 대부분이 온다고 한 이 지연이 여기서 잡힌다.
