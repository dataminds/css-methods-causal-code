
# 부록 B · AI가 한 분석을 검증하고 남기기 (검증 로그)

> 이 책의 전제: 분석 코드는 AI가 짜 주되, 그 코드를 믿을지는 연구자가 검증으로 판정한다. 검증 로그는 그 판정의 기록이다. 로그는 실습마다 한 문단, 논문이라면 분석마다 한 항목을 쓴다. ⭐ 검증은 **전부 코드로** 한다. 손계산은 검증 수단이 아니다(개념을 처음 배울 때 감을 잡는 용도까지만 쓴다). 검증 절차는 2장 §2.4에서 처음 나오고, 21장 §21.4가 통계 분석판으로 다시 정리한다. 이 부록은 그 절차를 AI에게 시키는 말과 기록하는 양식을 함께 준다. 이 부록의 지시문은 모의 자료를 올린다. 실제 응답자 자료라면 올리기 전에 2장 §2.4 「내 자료를 올리기 전에」를 먼저 따른다.
>
> ⭐ **검증은 자동화한다. 조건은 셋이다.** 분석은 서로 독립인 판 여럿이 따로 하고, 검증 명세(무엇과 무엇이 같아야 하는지 · 가짜 자료에서 무엇이 나와야 하는지)는 결과를 보기 전에 고정하고, 채택 여부는 미리 정한 판정 규칙이 가른다. 같은 대화의 같은 AI에게 「검증 코드도 알아서 만들어 줘」라고 맡기면 같은 오해에서 나온 검증이 같은 오류를 통과시킨다(22장 §22.3). 독립은 그 오해를 끊는 단위다.
>
> ⭐ **한 판의 오류는 판끼리의 대조로, 모든 판이 함께 갖는 오류는 모의 세계 시험(참값을 아는 자료)으로 잡고, 둘 다 못 잡는 것은 목록으로 밝힌다**(§B.6). 판은 1학기에 「AI 둘 × 파이썬」 두 판으로 시작하고, 2학기에 R을 더해 「AI 둘 × 파이썬 · R」 네 판으로 넓힌다(부록 G §G.1).

## B.1 검증 넷: 명세와 출력 대조 셋

2장 §2.4의 검증은 넷이다. 먼저 **명세**(파일 · 열 · 집단 · 필터 · 기대 인원)를 시키기 전에 정하고, 판마다 실제 인원을 출력으로 찍어 기대 인원에 견준다. 그다음 출력을 아래 표의 세 검사 가운데 하나 이상으로 대조한다. 사람은 코드를 한 줄씩 읽지 않는다. 코드는 검사가 실패하거나 판이 어긋날 때 원인을 찾으려고 연다. 명세는 출력을 보기 전에 정하는 것이라 번호 없이 표의 맨 앞에 놓고, 출력 대조 셋에 검사 1~3의 번호를 붙였다. 21장 §21.4와 부록 D가 말하는 「3종」이 출력 대조 셋이다.

| 검사 | 물음 | 결과보다 먼저 고정할 것 | 독립 판에게 시키는 것 | 이 책의 실물 예 |
|---|---|---|---|---|
| (앞선) 명세와 인원 | AI가 시킨 것을 계산했나 | 장마다 「AI에게 시키기」의 받은 답 판단 목록 ; 파일·열·집단·거른 조건 넷과 기대 인원 | 판마다 분석에 들어간 인원과 거른 조건을 출력으로 찍기 ; 대조 스크립트가 기대 인원과 견준다 | 2장 실습 4(엉뚱한 둘째 항 = 인원이 183이 아니다) ; 오류 찾기 노트북의 오류 메시지 없는 오류 여섯(부록 E) |
| 1. 독립 재계산 | 다른 판 · 다른 길로 계산해도 같은 값이 나오나 | **짝** = 어느 두 값이 같아야 하는가 · 허용폭 | 판마다 따로 계산해 한 표로 대조 ; 같은 판 안에서는 같은 양을 **다른 코드 경로**로 | *t*검정 *p* ↔ 뒤섞기 *p* (12장 · S1) ; 표준화 기울기 ↔ *r* (14장) ; 통제 계수 ↔ 층별 기울기 (15장) ; 회귀 b3 ↔ 셀 평균의 차이의 차이 (S2) ; 조건별 기울기 ↔ 집단을 나눠 맞춘 기울기 (16장 §16.4 「나눈 집단의 기울기와 단순기울기」) ; 간접효과 a × b ↔ c − c′ (17장 §17.1) ; 손으로 짠 `ols` ↔ statsmodels (부록 A §A.3b) |
| 2. 극단값 · 모의 세계 시험 | 정답을 아는 자료에 넣으면 그 정답이 나오나 | **가짜 자료와 기대값** (효과 0 = 뒤섞기·상수화 ; 완전 일치 = 복사본 ; 심은 참값 = 모의 세계) | 가짜 자료를 만들어 같은 분석 돌리기 | cond 뒤섞기 → 차이 ≈ 0 (S1) ; mil 상수화 → 기울기 0 (14장) ; X만 섞기 → 간접효과 ≈ 0 (17장 ; 22장 §22.4 「다른 분석이라면」) ; 코더 2 열을 코더 1 복사본으로 → 카파 1 (웹 시나리오 S6) ; 빈칸이 생기기 전 패널 → 3차 평균 4.77 (B5) |
| 3. 재실행 | 같은 씨앗에서 같은 수가 나오나 | 씨앗 · 반복 수 | 처음부터 끝까지 한 번에 도는 스크립트 하나를 **새 환경**에서 두 번 | 씨앗 73 재생성 → 본문 수치 일치 (전 장) |

「결과보다 먼저 고정할 것」 열은 분석 결과를 본 AI에게 묻지 않는다. 결과를 본 AI가 짝과 기대값을 정하면 그 결과에 맞는 짝과 기대값이 나올 수 있다. 그래서 검증 명세는 질문과 자료 설명만 받은 다른 AI(새 대화 · 다른 회사의 모형)가 분석보다 먼저 쓰게 하거나, 위 표의 실물 예에서 고른다. 재실행을 AI 대화 안에서 「다시 돌려 봐」로 시키면 앞의 계산이 남은 같은 환경에서 도는 것이라 재실행 시험이 아니다(§B.3b 코드 아래 ⚠). 받은 스크립트를 Colab에서 런타임을 다시 시작한 뒤 돌리거나, 새 파이썬 실행으로 돌린다. 이 실행도 스크립트 하나로 자동화할 수 있다.

### 판 대조: AI 둘 × 언어 둘

독립 재계산의 기본 장치는 판 대조다. 같은 질문과 같은 자료를 서로 다른 회사의 AI 둘에게 따로 주고, 각 AI에게 파이썬과 R로 따로 짜게 하면 판이 넷이다.

| | 파이썬 | R |
|---|---|---|
| AI ㄱ | 판 ① | 판 ② |
| AI ㄴ | 판 ③ | 판 ④ |

AI 축은 「AI의 오해」를, 언어 축은 「도구의 기본값 · 구현」을 흔든다. 한 판에만 있는 오류는 나머지 판과 어긋나서 드러난다. 이 책에서 실제로 드러난 예가 셋이다. 22장 §22.4의 AI 판 회귀는 절편 열을 빠뜨려 기울기 0.976을 냈다(바른 값 0.978). 파이썬 `ttest_ind`는 기본이 등분산 가정이고 R `t.test`는 기본이 웰치라, 같은 질문에 *p*가 다르게 나온다(§B.4 9행). 반올림 함수는 엔진마다 정확히 반인 값에서 다른 답을 낸다(부록 C).

⚠ **모든 판이 함께 틀리면 대조는 일치를 보인다.** B5의 패널 자료에서 「3차 삶의 의미 평균」을 시키면 파이썬 `mean`도 R `mean(na.rm = TRUE)`도 빈칸을 빼고 계산해 네 판이 모두 4.93을 낸다. 참값은 4.77이다(빠진 사람의 1차 점수가 낮았다 ; B5 §B5.3). 일치가 치우침을 가린다. 이런 공통 오류는 판을 늘려도 줄지 않는다. 그래서 **모의 세계 시험**을 따로 건다. 참값을 심어 만든 자료에 같은 분석 코드를 먼저 돌려, 심은 값이 나오는지 본다. 이 책의 모의 세계 자료는 모두 참값을 알고 만든 것이라 그대로 이 시험에 쓸 수 있다(B5라면 빈칸이 생기기 전 패널 `data/truth_panel.csv`).

⭐ **판 수는 학기마다 다르다.** 1학기는 「AI 둘 × 파이썬」 두 판과 모의 세계 시험으로 시작한다. 2학기에 R을 더해 네 판으로 넓힌다(R은 부록 A가 다리다).

네 검증은 잡는 오류가 다르다. 명세와 인원은 **엉뚱한 집단이나 빠진 필터로 생긴 그럴듯한 오류**를(엉뚱한 열은 검사 1의 판 대조가 함께 잡는다), 검사 1은 **코드의 논리**를, 검사 2는 **코드의 방향**(부호·영점)을, 검사 3은 **파이프라인의 결정성**(숨은 무작위·상태 오염)을 잡는다. 하나만 하면 나머지 셋이 잡을 오류가 새어 나간다. S2는 5부에 실린 시나리오이고, S6은 종이책에는 없고 웹에 있는 시나리오다(부록 E).

## B.2 로그 양식

로그는 분석 하나당 한 항목을 쓴다. 2장 §2.4가 말한 한 문단(시킨 것 · 확인한 것 · 판단 · 남은 의심)을 칸으로 나눈 것이 아래 양식이다. 시킨 것이 [AI], 확인한 것이 [인원]과 [검사1]~[검사3], 판단이 [판정], 남은 의심이 [의심]이다. 칸마다 오른쪽에 그 칸이 어디서 오는지 표시했다.

```
[분석] 무엇을 구했나 (예: S1 주 분석 ; 두 집단 삶의 의미 차이)            ← 내 질문
[명세] 결과보다 먼저 고정한 짝 · 기대값 · 허용폭 · 판정 규칙               ← 검증 명세 판 (분석 전)
[AI]   판마다 무엇을 시켰고 무엇을 받았나 (지시문 · 고른 분석 · 언어)      ← 판마다 그대로 옮긴다
[인원]  받은 답 판단 목록 + 파일·열·집단·거른 조건 넷 + 판마다의 인원        ← 판 출력
       + 빈칸 처리 · 점수 만들기(역채점 · 평균)가 의도와 같은가
[검사1] 판 대조: 판마다의 값을 한 표로, 허용폭 안인가                      ← 대조 스크립트
[검사2] 극단값 · 모의 세계: 가짜 자료와 기대값, 판마다의 실제 값            ← 대조 스크립트
[검사3] 재실행: 새 환경에서 두 번 돌린 결과                             ← 실행 스크립트
[판정]  채택 / 수정 후 채택(무엇을 고쳤나) / 기각(왜) = 판정 규칙의 결과    ← 판정 규칙
[의심]  자동화가 못 잡는 것(§B.6 표) 가운데 이 분석에 걸리는 것 · 설계 검토 의견
```

[검사1]·[검사2]의 수는 출력에서 그대로 옮기고 머리로 반올림하지 않는다(부록 C §C.3). [판정]은 [명세]에 미리 적은 규칙(예: 결정적 계산은 판끼리 차이 1e−8 안 · 모의 세계 시험은 심은 값이 구간 안)이 낸 결과다. 규칙 없이 「통과했습니다」라고 써 넣은 판정은 판정이 아니다.

## B.3 기입 예: 좋은 예와 나쁜 예 (S1 주 분석)

좋은 예부터 본다. S1은 5부의 두 집단 실험 시나리오이고, 12장이 같은 비교를 먼저 판정한다.

```
[분석] 실험판 주 분석: 정제 표본(366)에서 개입/통제의 사후 mil 비교
[명세] (분석 전 새 대화의 AI ㄴ) 짝 = 평균 차이 ↔ 0/1 회귀 계수 · 판끼리 · 허용폭 1e−8 ;
       극단값 = mil 을 모두 5로 → 차이 0 ; 판정 = 넷 다 통과면 채택
[AI]   (판 ① AI ㄱ · 파이썬) "올린 실험 자료에서 개입 집단의 삶의 의미가 통제 집단보다 평균적으로 얼마나 높은지 알고 싶어.
        문항을 제대로 읽었는지 확인하는 질문(attn_1)을 틀린 사람은 빼 줘 ; 코드를 짜서 직접 실행" 지시 ;
       고른 분석 = 두 집단 t검정 ; pandas 필터 + scipy ttest_ind 코드 수령
       (판 ③ AI ㄴ · 파이썬) 같은 질문 한 문단 ; 고른 분석 = 0/1 회귀 ; statsmodels 코드 수령
[인원]  받은 답 판단: 남은 인원 366 (3장과 같음) · 고른 분석과 이유를 밝힘.
       파일 journey_exp.csv · 열 mil · 집단 cond 1 대 0 · 거른 조건 attn_1 == 1. 의도와 같음
[검사1] 판 ① 평균 차이(5.26 − 4.98) 0.283 ↔ 판 ③ 0/1 회귀의 cond 계수 0.283 ; 허용폭 안. 통과
        (참고) t검정 p=.028 ↔ 뒤섞기 5,000회 p=.030 ; 서로 다른 두 검정이라 근사 일치만 기대한다
[검사2] mil 을 모두 같은 값 5로 바꾼 가짜 자료 → 예측: 차이 정확히 0 → 실제 0.0. 통과.
        cond 를 1,000번 섞은 영세계 → 예측: 차이 평균 ≈ 0 → 실제 0.0015 ± 0.133. 통과
[검사3] 받은 스크립트를 Colab 런타임 다시 시작 후 두 번 실행 → 5.26/4.98/t=2.21 두 번 다 재현. 통과
[판정]  채택 (명세의 규칙 넷 모두 통과)
[의심]  ttest_ind 기본값(등분산 가정)을 그대로 받았다. 두 집단 SD가 비슷해 웰치와 차이가 없을 것으로 보이나 아직 안 돌렸다(12장 §12.5 ;
       2학기에 R 판을 더하면 R 기본값이 웰치라 이 차이가 대조에서 드러난다). 무작위 배정이라 혼란 걱정은 작다(§B.6 표 넷째 줄)
```

나쁜 예도 하나 보자. 같은 분석의 로그다.

```
[분석] t검정
[AI]   t검정 코드 받음
[검사]  돌려 보니 잘 나옴
[판정]  채택
```

나쁜 예에는 무엇을 시켰는지(파일·열·집단·필터), 인원이 명세와 맞는지, 출력을 무엇과 대조했는지, 무엇이 남았는지가 하나도 없다. 「돌려 보니 잘 나옴」은 코드가 오류 메시지 없이 돌았다는 뜻일 뿐이고, 2장 §2.4가 경고한 그럴듯한 오류도 메시지 없이 돈다. 나쁜 예의 로그로는 석 달 뒤의 자기도, 심사자도 판정을 되짚을 수 없다. 미리 정한 규칙 없이 AI가 「모든 검사를 통과했습니다」라고 써 준 [판정]도 나쁜 예와 같다. 판정은 [명세]의 규칙이 낸 것일 때만 판정이다.

## B.3a 검증을 시키는 지시문

검증 지시문도 장마다의 지시문과 같은 원칙으로 쓴다(일상어로 · 아는 것만). 다른 점은 순서다. **검증 명세를 분석보다 먼저** 받아 고정하고, 분석은 판마다 따로 시키고, 대조와 판정은 스크립트가 한다. 아래는 S1 주 분석의 본보기다. 대화가 셋으로 나뉜다.

**대화 ㄱ · 검증 명세 (분석 전 ; AI ㄴ의 새 대화)**

```text
올린 실험 자료(journey_exp.csv)로 개입 집단의 삶의 의미가 통제 집단보다 얼마나 높은지 분석할 거야. 아직 분석은 하지 않았어. 이 분석을 검증하려면 무엇과 무엇이 같아야 하는지, 결과를 이미 아는 가짜 자료를 어떻게 만들면 무엇이 나와야 하는지, 판끼리 얼마나 다르면 어긋난 것으로 볼지를 목록으로 정해 줘. 목록은 결과 이름 · 기대값 · 허용폭 칸의 표로 줘.
```

**대화 ㄴ · 분석 (판마다 새 대화 ; 1학기 = AI ㄱ 파이썬 · AI ㄴ 파이썬)**

```text
올린 실험 자료(journey_exp.csv)에는 응답자가 문항을 제대로 읽었는지 확인하는 질문(attn_1)이 있어. 그 질문을 틀린 사람은 빼고 분석해 줘. 집단 열은 cond이고 1이 개입, 0이 통제야. 개입 집단의 삶의 의미가 통제 집단보다 평균적으로 얼마나 높은지 알고 싶어. 분석은 파이썬으로 코드를 짜서 직접 실행하고, 그 코드와 실행 결과를 함께 보여 줘. 결과는 result_판이름.csv 파일에 결과 이름 · 값 두 열로도 저장해 줘. 결과 이름은 아래 목록을 그대로 써 줘. [대화 ㄱ에서 받은 결과 이름 목록]
```

**대화 ㄷ · 대조와 판정 (스크립트 받기)**

```text
판마다 저장한 result_*.csv 파일들과 검증 명세 표(spec.csv)를 읽어서, 결과 이름마다 판끼리의 값을 한 표로 나란히 놓고 허용폭 안인지 표시하는 파이썬 스크립트를 짜 줘. 가짜 자료 시험의 기대값과 실제 값도 같은 표에 넣어 줘. 하나라도 허용폭을 넘으면 맨 아래에 「불일치」와 그 결과 이름을 찍어 줘. 스크립트는 처음부터 끝까지 한 번에 돌게 해 줘.
```

대화 ㄱ이 분석 결과를 보지 못한 채 명세를 쓰므로, 기대값이 결과에 맞춰질 수 없다. 대화 ㄴ은 판마다 질문 한 문단만 같고 방법은 각 AI가 고른다. 두 AI가 다른 방법을 골랐으면(위 좋은 예처럼 *t*검정과 0/1 회귀) 그 자체가 독립 재계산의 짝이 된다. 대화 ㄷ의 스크립트와 받은 분석 코드는 대화 밖에서 새 환경으로 돌린다(§B.1 검사 3). 짝을 명세 판도 정하지 못하면 §B.1 표의 실물 예에서 고르고, 그래도 없으면 검사 1을 건너뛰었다고 [의심] 칸에 밝힌다(아래 §B.3b 끝).

⚠ **판정 규칙의 관문 시험.** 처음 한 번은 판 하나에 일부러 오류를 넣어(절편 빼기 · 집단 뒤바꾸기 · 빈칸을 그대로 두기) 대조 스크립트가 「불일치」를 찍는지 본다(22장 §22.5). 망가뜨린 판을 통과시키는 대조는 관문이 아니다.

## B.3b 극단값 시험과 재실행을 한 덩어리로 (받은 코드의 한 예)

극단값 시험을 실습마다 새로 시키지 말고 함수 하나로 받아 두면 다음부터는 몇 줄로 끝난다. 이렇게 시킨다.

```text
분석 하나를 함수로 받아서, 내가 고른 열을 1,000번 뒤섞은 가짜 자료들로 같은 분석을 되풀이하는 함수를 만들어 줘. 원래 값, 뒤섞은 값들의 평균과 표준편차를 찍어 줘. 씨앗은 73으로 고정하고 횟수와 씨앗을 바꿀 수 있게 해 줘. 내 예상은 뒤섞은 값들의 평균이 0 근처라는 거야.
```

아래는 그렇게 받을 수 있는 코드의 한 예다. 3장의 `load`로 정제된 실험판(366명)을 읽고, 주 분석(개입 평균 − 통제 평균)을 함수로 만든 뒤, cond를 1,000번 뒤섞은 영세계의 평균과 폭, 그리고 같은 세션에서 한 번 더 부른 결과를 찍는다. 받은 코드에서 짚을 곳은 셋이다. 뒤섞는 열이 내가 고른 cond인가(`섞을열`), 씨앗이 함수 안에서 한 번만 정해지는가(`default_rng(씨앗)`), 원본 자료를 바꾸지 않고 복사본을 섞는가(`df.copy()`).

```python
import numpy as np, pandas as pd
from scipy import stats
exp = load("exp")

def 주분석(df):
    return df[df.cond == 1].mil.mean() - df[df.cond == 0].mil.mean()

def 검증(계산, df, 섞을열, 반복=1000, 씨앗=73):
    본값 = 계산(df)
    rng = np.random.default_rng(씨앗)
    영값 = []
    for _ in range(반복):
        가짜 = df.copy()
        가짜[섞을열] = rng.permutation(df[섞을열].values)
        영값.append(계산(가짜))
    재실행 = 계산(df)
    print("본값", round(본값, 4))
    print("영세계", round(float(np.mean(영값)), 4), "±", round(float(np.std(영값, ddof=1)), 3))
    print("같은 세션 반복 일치", 본값 == 재실행)
    return 본값, np.array(영값)

검증(주분석, exp, "cond")
# 본값 0.2828
# 영세계 0.0015 ± 0.133
# 같은 세션 반복 일치 True
```

출력의 첫 줄은 주 분석의 값(0.2828 ; 12장의 0.283)이고, 둘째 줄이 극단값 시험(검사 2)이다. 셋째 줄은 같은 세션에서 같은 함수를 한 번 더 부른 빠른 확인이다. 주 분석 함수 안에 씨앗 없는 무작위가 있으면 False가 나와 문제 위치를 좁혀 준다. ⚠ 이것은 재현 시험(검사 3)이 아니다. 재현 시험은 커널을 다시 시작해 처음부터 돌리는 것이다(좋은 예의 [검사3]). 같은 세션 안에서는 앞에서 만든 변수가 남아 있어, 처음부터 돌리면 깨지는 코드도 True를 낸다.

⚠ 둘째 줄의 극단값 시험은 **여러 번 뽑는 것이 요령**이다. 한 번만 뽑으면 씨앗 73에서 0.135가 나오는데, 0.135만 보면 "극단값 시험 실패"로 오독하기 쉽다. 영세계에서도 한 판은 얼마든지 크게 나온다(±0.133이 그 폭이다). **검사할 것은 한 판의 값이 아니라 영세계의 중심이 0인가**이다. ±0.133이라는 폭은 12장 §12.2에서 뒤섞기 5,000번으로 만든 영분포의 퍼짐(0.130)과 같은 양이고, 두 계산이 뒤섞기를 따로(횟수도 다르게) 해서 소수 셋째 자리만 다르다.

명세와 검사 1(독립 재계산)은 함수로 못 묶는다. 명세는 분석마다 내가 정하는 것이고, 독립 재계산은 대상마다 짝이 다르다(그래서 짝은 지시문마다 내가 정한다 ; §B.3a ①). 독립 재계산의 **짝**은 §B.1의 표에서 고른다. 자기 분석에 맞는 짝이 표에 없으면, 짝이 없다는 사실이 곧 "이 수치를 다른 길로 구할 방법을 아직 모른다"는 신호이므로 검사 1을 건너뛰었다고 로그의 [의심] 칸에 밝힌다. **못 한 검사를 안 했다고 밝히는 것이 로그의 최소 정직이다.**

## B.4 받은 코드에서 먼저 확인할 실패 열두 가지 (오류 메시지 없이 지나가는 것)

아래 열두 가지는 코드가 멀쩡히 돌고 결과도 그럴듯한 수로 나온다. 그래서 출력만 봐서는 못 잡고, 표의 둘째 열에 있는 신호를 일부러 찾아야 드러난다. 받은 답마다 2장 §2.4의 「먼저 세 가지」(분석 인원 · 뺀 사람과 그 기준 · 빈칸 처리)부터 확인한다. 1행과 6행은 이 확인에서 걸린다. 셋째 열은 AI에게 바로 확인시키는 한 줄이다. 넷째 열의 절에서 그 실패를 자세히 다룬다.

## B.5 로그를 언제 쓰나

로그를 쓰는 시점은 셋이다.

**분석 직후.** 기억이 남아 있을 때 쓴다. 하루 지나면 "왜 이 표본이었는지"를 다시 추적해야 한다.

**결과가 바뀔 때마다.** 자료를 다시 받았거나 기준을 고쳤으면 그 항목을 새로 쓴다. 덮어쓰지 말고 **덧붙인다.** 무엇이 언제 왜 바뀌었는지 남아 있으면, 나중에 변경을 의심받을 때 그 기록이 자기를 지켜 준다(3장과 21장 §21.6의 "바꾸는 것이 죄가 아니라 숨기는 것이 죄다").

**투고 직전.** 본문 수치와 로그의 수치를 한 번 대조한다. 분석을 다시 돌려도 원고의 수는 따라오지 않는다. 20장 §20.6은 수치 오류 가운데 많은 수가 분석과 원고 사이의 이 지연에서 온다고 했다. 투고 직전의 대조가 그 지연을 잡는다.

## B.6 자동화 검증이 지킬 조건과 자동화가 못 잡는 것

검증은 처음부터 끝까지 자동화할 수 있다. 다만 아래 다섯 조건을 지켜야 자동화가 검증이 된다. 하나라도 빠지면 같은 오해가 검증을 통과한다.

1. **독립.** 분석 판은 서로 다른 회사의 AI, 새 대화, 다른 언어로 나눈다. 같은 대화의 같은 AI에게 검증까지 맡기면, 집단을 잘못 나눈 AI가 잘못 나눈 집단이 잘 나뉘었는지를 검사한다(22장 §22.3).
2. **명세 선고정.** 짝 · 기대값 · 허용폭 · 판정 규칙은 분석 결과를 보기 전에, 결과를 보지 않은 판이 정한다(§B.3a 대화 ㄱ). 결과를 본 뒤에 정한 기대값은 결과에 맞춰질 수 있다.
3. **지시문은 질문만 같게.** 판마다 질문 한 문단만 같게 주고 방법은 각 판이 고르게 한다. 방법까지 적은 같은 지시문을 모든 판에 복사하면 지시문의 잘못이 모든 판의 공통 오류가 된다.
4. **새 환경 재실행.** 대화 안의 「다시 돌려 봐」가 아니라 새 환경에서 스크립트를 처음부터 돌린다.
5. **관문 시험.** 판 하나를 일부러 망가뜨렸을 때 대조가 「불일치」를 내는지 처음에 한 번 본다(22장 §22.5). 실패시킬 수 없는 관문은 관문이 아니다.

⭐ **모든 판이 함께 틀리는 것.** 판 대조는 한 판에만 있는 오류를 잡는다. 모든 판이 함께 갖는 오류에는 대조가 일치로 답한다. 그래서 따로 잡는 장치가 필요하고, 계산으로 잡히지 않는 것은 목록으로 밝힌다.

| 모든 판이 함께 틀리는 것 | 예 | 잡는 장치 |
|---|---|---|
| 같은 관행 | 빈칸을 말없이 빼고 평균한다 = 네 판 모두 4.93, 참값 4.77 (B5 §B5.3) | 모의 세계 시험 (참값을 아는 자료로 먼저 돌린다) |
| 같은 지시문 | 지시문이 질문을 잘못 정하면 모든 판이 그 잘못된 질문에 정확히 답한다 (22장 §22.6 첫째) | 조건 3 + 결과를 본 적 없는 AI의 설계 검토 의견 ([의심] 칸) |
| 같은 자료 | 역채점 누락 · 잘못 병합된 열 (22장 §22.6 셋째 ; §B.4 2 · 3행) | 자료 점검 출력 (문항-총점 상관 · 자료형 · 병합 전후 행 수) |
| 타당도 | 빠뜨린 혼란변수 · 횡단 자료의 인과 해석 · 측정이 개념과 어긋남 | 계산 검증으로는 못 잡는다. 결과를 본 적 없는 AI에게 「이 질문과 설계로 이 결론을 말할 수 있는가」를 묻고, 그 답을 [의심] 칸에 검토 의견으로 남긴다 |
| 닮은 오해 | 두 AI가 같은 관행으로 학습돼 같은 실수를 한다 | 언어 축을 더한 네 판(2학기) + 모의 세계 시험. 독립은 커지지만 0이 되지는 않는다 |
| 모든 검사를 통과하는 다른 틀린 답 | 불변식은 답의 범위를 좁힐 뿐 하나로 정하지 않는다 (22장 §22.6 둘째) | 없음. 통과는 로그에 「아직 안 걸렸다」로 남긴다 |

⚠ **AI가 써 준 「통과했습니다」는 검사 결과가 아니라 문장이다.** 지어낸 수와 계산된 수가 겉으로 구별되지 않듯(1장 §1.3), 지어낸 판정과 규칙이 낸 판정도 문장만으로는 구별되지 않는다. 판정은 대조 스크립트의 출력에서만 옮긴다.
